- 前端 `App.vue:891` 直连 `ws://localhost:8000/ws`——这是**旧版 Python 单体**（`backend/main.py:391` 监听 8000），承载视频帧、音频上传、TTS 下发、心跳等核心流量；

### P0-3 ✅ ChatController 自建无界线程池 + SSE 回调二次注册
- `ChatController.java:65`：`Executors.newCachedThreadPool()` 作为实例字段，**无 shutdown 钩子**——每请求峰值时会无上限创建线程；

## P2 — 工程化缺陷

### P2-1 启动脚本 5 套并存且互相漂移
根 `start_all.ps1`（主入口）、根 `start_all.sh`、`backend/start_all.sh`（与根版 95% 重复，仅日志路径不同）、`backend/start_all.bat`、`backend/start_java.bat`。漂移点：① Redis 三种启动方式（bat 用 `redis.persist.conf`，两个 sh 用裸 `redis-server`，ps1 只检查不启动）；② venv 检查名不一致（sh/bat 找 `venv2.0`，ps1 检查 `venv`）；③ `backend/start_java.bat:3-5` 硬编码 `C:\Users\YangYiTao\...` 个人绝对路径，换机即死。

### P2-2 吞异常文化盛行
Java 侧 23 个 catch 中 22 个仅 log 后继续；`FeedbackServiceImpl.java:68-70` MySQL 写失败静默丢数据；`ConversationController.java:140-143` 吞异常返 null。Python 侧 92 个 except，其中裸 `except Exception: pass` 5 处（如 `websocket_client.py:43-44`）。配合 P0-3 的"故障伪装成正常帧"，系统故障时用户和开发者都得不到真实信号。

### P2-3 TTS 幽灵导入（配置即崩）
`Agent/src/utils/tts.py:32-46` 在**模块导入时**按 `_TTS_PROVIDER` if/elif 导入——但 `volcengine` 分支要导入的 `src/utils/volcengine_tts.py` **不存在**。把 .env 的 TTS_PROVIDER 改成 volcengine，服务启动即 ImportError。说明该分支从未被运行验证过。

### P2-4 数据层三处埋雷
- 对话历史**只存 Redis、2h TTL**（`ChatController.java:128-130`）——两小时后上下文静默蒸发，MySQL 只存 Agent 回调的会话日志；
- Flyway migration 不全：`session_logs` 建表只存在于根目录 `database_init.sql:45`，不在 `backend/src/main/resources/migration/`（V001/V002 之外）；
- `database_init.sql` 在 README/启动指南均未提及（靠口头约定手动执行）；根目录 `requirements.txt` 自称"统一依赖清单"但与子目录版本有差异，且所有启动脚本实际安装的是各子目录 requirements——**无人使用**。

### P2-5 API 契约两份且双双漂移
`backend/API_Contract.md:72` 的 SSE 末帧示例缺 `intervention_alert` 字段（前端版和实际实现都有）；两份契约**均未记载**实际在用的 `POST /api/v1/feedback`（`FeedbackController.java:28`，前端 `App.vue:1276` 在调）和 `/internal/conversation/log`（`ConversationController.java:40`，Agent 回调在用）。

### P2-6 靠赌的启动顺序
前端会话初始化重试 20 次 × 3s（`App.vue:186-222`）——用前端硬重试掩盖"后端没起好"的时序问题；感知权重、Agent 拉取感知数据均为惰性拉取，无就绪探针（`scripts/smoke_check.ps1` 存在但不在启动主链路）。
