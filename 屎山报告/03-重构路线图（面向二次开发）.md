# 屎山报告三：重构路线图（面向二次开发）

> 前提认知：这个项目"基本功能能跑"，且比赛作品已交付——**重构的目标不是推倒重来，而是让下一个功能只付一份成本**。路线按"止血 → 清尸 → 定规矩 → 减脂 → 铺路"五个阶段推进，每阶段独立可停，做完任一阶段系统都比之前好。
> 原则：每阶段结束跑通一次全链路对话（文字+语音+干预弹窗），再进下一阶段。

---

## Phase 0：止血（半天，建议今天就做）

1. **密码出库**（P0-1）：`application.yml` 改为
   ```yaml
   username: ${MYSQL_USERNAME:root}
   password: ${MYSQL_PASSWORD:}
   ```
   并把真实值放进本地 `backend/.env`（该文件已被正确 ignore）。远端仓库历史里的密码无法静默消除——改密码本身（MySQL + 任何复用该密码的地方）比清洗 git 历史更重要。
2. **删掉 `backend/start_java.bat`**（硬编码个人路径，换机即死），或改为相对路径。
3. **修 TTS 幽灵导入**（P2-3）：`tts.py` 导入失败时 log 警告并降级到 edge-tts，而不是启动即崩。

## Phase 2：定单一事实源（1-2 天）

这阶段解决"约定靠复制"的根基病灶，是二次开发前性价比最高的一步：

1. **API 契约合一**（P2-5）：删除两份 `API_Contract.md`，合并为 `docs/API_CONTRACT.md` 一份，补上实际在用但未记载的 `POST /api/v1/feedback`、`/internal/conversation/log`。规则：改接口先改契约。
2. **常量单源化**（P1-3）：
   - 前端：新建 `frontend/src/constants/emotions.js` 导出 EMOTION_MAP，App.vue 与 store 都从这里 import；
   - 感知阈值/权重：**只留在感知服务**（perception/config），Agent 不再自带副本——Agent 消费感知服务产出的 focus 字段即可，不重复计算；
   - Redis key：新建 `docs/REDIS_KEYS.md` 或在后端建 `RedisKeys.java` 常量类 + Agent 建对应常量模块，key 格式、TTL、trim 规则写明，废掉"与 Python 端保持一致"式注释。
3. **启动脚本收敛**（P2-1）：只保留 `start.ps1`（Windows）+ `start.sh`（Unix）各一份于仓库根，内含：Redis 启动/检查统一逻辑、venv 统一为一个名字、日志统一 `logs/`。其余三套删除。
4. **前端 API 层 + 环境变量**（P1-2 前置）：新建 `frontend/src/api/index.js`，`const BASE = import.meta.env.VITE_API_BASE ?? 'http://localhost:8080'`，`VITE_WS_URL` 同理；`.env.example` 进 frontend。4 处硬编码 URL 全部改走这里。

## Phase 3：前端拆分（3-5 天，可与 Phase 4 并行）

把 App.vue 从 1399 行拆回 UI 编排（目标 < 300 行），纯机械搬移、不改行为：

```
frontend/src/
├── api/index.js            # fetch 封装（会话/聊天 SSE/反馈上报）
├── constants/emotions.js   # EMOTION_MAP/PULSE_MAP 单源
├── composables/
│   ├── useSession.js       # 会话初始化+重试（App.vue:186-222）
│   ├── useVoiceInput.js    # 采集→重采样→WAV→base64（224-591，约370行）
│   ├── useAudioPlayer.js   # MediaSource 播放队列（593-883，约290行）
│   ├── usePerceptionSocket.js # WS 总线+心跳+重连（885-1145）
│   └── useAgentChat.js     # SSE 解析+abort（1147-1269）
└── App.vue                 # 只剩模板+编排+生命周期清理
```

搬移纪律：每抽一个 composable 就跑一次语音对话回归；非响应式的 `let socket/mediaRecorder/...` 随所属 composable 走，onUnmounted 自清理。顺手修掉：`defineExpose` 删除、`debugEmotionType` 改走 action、死状态 `viewMode` 删除。

## Phase 4：后端减脂（2-3 天）

1. **ChatController 瘦身**（P1-5）：新建 `ChatService`（编排）、`ConversationHistoryService`（Redis 历史+TTL+trim，Java 侧唯一入口）、弹窗文案挪进 `InterventionService`；控制器只剩参数校验 + SSE 装配。
2. **线程池**（P0-3）：删掉自建 `newCachedThreadPool`，改用 Spring 管理的 `ThreadPoolTaskExecutor` bean（有界队列+拒绝策略）；删掉 `:111` 的空回调二次注册。
3. **故障语义**（P0-3/P2-2）：`AgentClient` 服务不可用时发显式 `event: error` 帧（前端已有错误提示路径），不再伪装正常回复；`FeedbackServiceImpl` 写库失败至少向上抛或计入错误计数。
4. **Agent 侧去重**（P1-4/P1-6）：Redis 三客户端合并为 `utils/redis_client.py` 一份；`_clean_llm_json/_get_deepseek_client` 抽到 `src/utils/llm_common.py`。

## Phase 5：为二次开发铺路（持续投入，按新功能需要逐项做）

- **鉴权**（P3-7）：sessionId 升级为签名 token（哪怕 HMAC 即可），中间件统一校验；
- **prompt 外置**：Agent 的 system prompt 挪到 `Agent/prompts/` 独立文件 + 版本号，改话术不再动代码；
- **黄金用例测试**：干预决策（五因子）、情感融合（OCC）各补 10 个左右确定性用例——这两处是调参重灾区，没有回归测试每次改权重都是赌博；
- **可观测性**：三服务统一日志格式 + 贯穿 traceId（前端生成，随 header/WS 消息传遍 8080→8001→8000）；
- **就绪探针**：启动脚本等各服务 healthcheck 通过再起下一个，废掉前端"重试 20 次×3s"（P2-6）。

## 新功能接入点指引（重构后）

| 新功能类型 | 加在哪里 | 不要加在哪里 |
|---|---|---|
| 新对话能力/人设/工具 | `agent/src/agent/nodes/` + `graph.py` 加节点 | 不要在旧 perception 的 main.py 里写对话逻辑 |
| 新感知模态（如打字节奏） | `perception/`（原 ai_assistant）+ 感知配置 | 不要在 Agent 里重新实现感知 |
| 新数据展示（图表/面板） | frontend 新组件 + store + WS 消息类型 | 不要再往 App.vue 里塞 |
| 新持久化实体 | Java entity + mapper + **补全 Flyway migration** | 不要再造 jsonl 文件 |
| 新第三方服务 key | `.env` + 对应 config 类 | 不要写进任何被 git 追踪的文件 |

## 一句话总结

这座屎山的病根是**"只加不删"**：Phase 0-1 把欠的删掉，Phase 2 把复制的收敛成一份，Phase 3-4 把超载的拆开——之后每个新功能就只需要写在一个明知道的地方。
