## 1.如何进行主动关怀？进行怎么样的主动关怀？

### 1.1 判断“合适”的主动关怀时机？

核心答案：时机决策是多因素综合权衡的结果，由Agent的`decide_intervention`节点负责。这个节点结合规则和LLM推理，输入包括当前情绪、打扰成本、历史趋势、置信度等，输出干预决策。

| 因素 | 来源 | 说明 |
|------|------|------|
| 情绪强度 | `emotion_vector.intensity` | 强度越高，干预必要性越大。 |
| 情绪类型 | `emotion_vector.primary_emotion` | 某些情绪（如恐慌、愤怒）可能需要更紧急干预。 |
| 打扰成本 | `interruptibility` 工具 | 成本越高，越应避免干预。基于当前应用重要性、专注度、空闲时间等。 |
| 历史趋势 | 情感记忆库 | 若情绪持续恶化（如强度曲线上升），应提前干预；若只是瞬时波动，可观察。 |
| 置信度 | `emotion_vector.confidence` | 置信度低时，可能先不干预，或先通过对话澄清。 |
| 上次干预时间 | Agent记忆 | 避免频繁干预（频率惩罚）。 |

#### 决策逻辑设计

- **规则层**：快速过滤不适宜干预的情况。
  - 若打扰成本 > 阈值（如0.8），则直接 `suggested_action = "silent"`。
  - 若情绪强度 < 阈值（如0.4），则 `suggested_action = "silent"`。
  - 若距离上次干预时间 < 冷却期（如2分钟），则 `suggested_action = "silent"`。
- **LLM层**：对于规则未直接否决的情况，将多因素转化为Prompt，让LLM综合判断。

```
【当前用户状态】
- 情绪：焦虑，强度0.85（置信度0.9）
- 打扰成本：0.3（低）
- 历史趋势：过去30分钟情绪强度从0.5上升至0.85，呈持续恶化趋势
- 上次干预时间：10分钟前
- 任务上下文：处于陪伴任务间隙

【你的任务】
请决定是否需要主动关怀用户。考虑以下原则：
1. 情绪强度高且持续恶化时，优先干预。
2. 打扰成本低时，更应积极介入。
3. 避免频繁干预（上次干预不久则谨慎）。
4. 置信度高时更可信。

请从以下动作中选择一个：silent（不干预）、subtle（仅UI变化）、intervene（显式对话）。
输出JSON格式：{"suggested_action": "intervene", "urgency": "high", "reasoning": "..."}
```

`decide_intervention`节点的输出应包含：

```json
{
```

### 1.3 变量获取总结

| 变量 | 来源 | 具体定义/计算方法 |
|------|------|------------------|
| 情绪强度 | `emotion_vector.intensity` | 0~1浮点数，由LLM在`fuse_emotion`节点输出。 |
| 情绪类型 | `emotion_vector.primary_emotion` | 枚举值（焦虑、沮丧、愤怒等），由LLM输出。 |
| 打扰成本 | 由`assess_interruptibility`工具计算 | 基于`state`中的`focus_level`（专注度）和`arousal`（唤醒度）估算。公式：`cost = focus_level * (1 - arousal)`，或更简单的规则（见下文）。 |
| 历史趋势 | 情感记忆库查询 | 查询最近30分钟内的情绪强度记录，计算斜率（线性回归）或比较最近几次的均值变化。 |
| 置信度 | `emotion_vector.confidence` | 0~1浮点数，由LLM在输出时自我评估。可通过prompt要求LLM给出。 |
| 上次干预时间 | Agent状态（`last_intervention_time`） | 记录上一次执行干预的时间戳，计算当前时间差（秒）。 |

#### 打扰成本估算（无需系统级监控）

- `focus_level`（专注度）：由MediaPipe头部姿态稳定性估计（0~1）。
- `arousal`（唤醒度）：来自`emotion_vector`或音频特征（0~1）。
- 沉浸感指标：当`focus_level`高且`arousal`低时，用户可能处于深度工作/阅读状态，打扰成本高。

简化公式：
```
interrupt_cost = focus_level * (1 - arousal)
```
- 若无`focus_level`，可默认设为0.5，或根据`blink_rate`、`head_pose`等粗略估计。
- 阈值：`cost > 0.6` 时认为打扰成本高，应避免干预。

### 1.4 详细说明：核心参数定义与计算

#### 一、核心参数定义与计算

1. **focus_level（专注度）**  
   定义：反映用户当前对主要任务的投入程度，0~1，越高表示越专注。  
   计算方式（基于现有感知数据，无需屏幕捕获）：
   - 头部姿态稳定性：通过MediaPipe获取头部欧拉角（pitch, yaw, roll），计算最近5秒内角度的标准差。标准差越小，头部越稳定，专注度越高。
   - 眨眼频率：正常专注时眨眼频率会降低（约15-20次/分），过高或过低可能表示分心或疲劳。可归一化处理。
   - 视线方向变化：若视线长时间偏离屏幕中央（如低头看书），可通过头部俯仰角（pitch）判断，低头角度大于15°可能表示阅读或思考，仍可能是专注状态。需结合任务上下文，但若无上下文，可简单视为专注。
   - 综合公式：
     ```
     focus_level = w1 * (1 - head_stability) + w2 * (1 - |blink_rate - 15|/15) + w3 * (1 - gaze_deviation)
     ```
     权重需实验标定，初期可简单平均。若无视线数据，可只用头部稳定性和眨眼频率。

2. **arousal（唤醒度）**  
   定义：反映用户生理心理的激活程度，0~1，越高越激动。  
   计算方式（已有数据）：
   - 音频特征：openSMILE输出的音调（pitch）和能量（energy），可归一化。音调高于基线、能量大表示高唤醒。
   - AU强度：AU4（皱眉）和AU1（内眉上扬）等与 arousal 正相关。可计算相关AU的加权和。
   - 眨眼频率：紧张时眨眼频率增加。
   - 综合公式：
     ```
     arousal = w4 * norm(pitch) + w5 * norm(energy) + w6 * norm(blink_rate) + w7 * norm(AU_arousal)
     ```
     同样需归一化，初期可用平均。

3. **打扰成本 interrupt_cost**  
   定义：干预可能对用户造成的打扰程度，0~1，越高越应避免干预。  
   计算公式（基于 focus_level 和 arousal）：
   ```
   interrupt_cost = focus_level * (1 - arousal)
   ```
   解释：高专注且低唤醒时，用户处于深度工作状态，打扰成本最高；低专注或高唤醒时，打扰成本降低。

4. **情绪强度 intensity**  
   定义：`emotion_vector.intensity`，由LLM融合多模态数据后输出，0~1。  
   获取方式：已在 `fuse_emotion` 节点中实现，通过Prompt让LLM生成。

5. **情绪类型 primary_emotion**  
   定义：枚举值，由LLM输出，需与吕思钒定义的情绪列表一致。  
   优先级：可预先定义情绪类型的干预优先级（高、中、低）。

6. **置信度 confidence**  
   质疑：LLM自我报告的置信度是否可靠？  
   改进方案：采用多模态证据一致性来修正LLM的置信度。
   - 计算各模态证据（AU、音频、Qwen分析）对最终情绪判断的支持度。例如，若AU强烈指向“焦虑”，Qwen也输出“焦虑”，则一致性高。
   - 定义一致性得分 `consistency`（0~1），与LLM输出的 `confidence_llm` 结合：
     ```
     confidence = alpha * confidence_llm + (1 - alpha) * consistency
     ```
     `alpha` 可取0.6，初期信任LLM多一些。随着数据积累，可调整。
   - 若LLM未输出 `confidence_llm`，则直接用 `consistency`。

7. **历史趋势 trend**  
   定义：过去一段时间情绪强度的变化趋势，枚举值（上升/下降/平稳）。  
   计算方式：
   - 从情感记忆库查询最近30分钟内的情绪强度记录（至少3个点）。
   - 计算线性回归斜率 `slope`，或比较最近两次与更早两次的均值。
   - 阈值设定：
     - 若斜率 > 0.1/分钟（或强度持续上升），则为上升趋势。
     - 若斜率 < -0.1/分钟，则为下降趋势。
     - 否则平稳。
   - 若无足够历史数据，默认平稳。

8. **上次干预时间 last_intervention_time**  
   定义：记录上次执行显式干预（intervene）或微干预（subtle）的时间戳。  
   冷却期：基础冷却期 `cooldown_base = 120`秒。若距离上次干预时间 < `cooldown_base`，则除非满足紧急条件，否则不干预。  
   紧急条件：情绪强度 > 0.9 且情绪类型为高优先级（愤怒、恐惧、恐慌）。

### 1.5 决策规则与公式

我们采用评分制+阈值，将多变量综合为一个干预倾向分数，然后根据分数决定动作。

#### 干预倾向分数 `intervention_score` 计算公式

```
intervention_score = 
    w_intensity * intensity 
    + w_emotion * emotion_priority(primary_emotion) 
    - w_cost * interrupt_cost 
    + w_trend * trend_factor(trend) 
    + w_confidence * confidence
```

其中：
- `emotion_priority` 映射：高优先级=1.0，中优先级=0.5，低优先级=0。
- `trend_factor`：上升趋势=0.2，下降趋势=-0.1，平稳=0。
- 权重暂定（可调整）：`w_intensity=0.5`, `w_emotion=0.3`, `w_cost=0.4`, `w_trend=0.2`, `w_confidence=0.1`。注意 `interrupt_cost` 是减项。

#### 决策逻辑

- 若 `intervention_score` ≥ 阈值（如0.6），且不违反冷却期，则执行干预。
- 干预动作分级：
  - **intervene**（显式对话）：当 `intervention_score ≥ 0.8` 或 情绪类型为高优先级且强度>0.7。
  - **subtle**（仅UI变化）：当 `0.6 ≤ intervention_score < 0.8`。
  - **silent**：否则。

- 冷却期逻辑：若 `now - last_intervention_time < cooldown_base`，则只有满足紧急条件才执行 `intervene`，否则 `silent`。

### 1.7 决策公式完整版

```python
# 计算分数
score = 0.5 * intensity \
        + 0.3 * emotion_priority(emotion) \
        - 0.4 * interrupt_cost \
        + 0.2 * trend_factor \
        + 0.1 * confidence

# 冷却期检查
if now - last_intervention < 120:
    if intensity > 0.9 and emotion_priority == 1:
        action = "intervene"
    else:
        action = "silent"
else:
    if score >= 0.8:
        action = "intervene"
    elif score >= 0.6:
        action = "subtle"
    else:
        action = "silent"
```

此公式可在初期硬编码，后期通过实验数据优化权重和阈值。所有参数均可从现有模块获取，无需额外复杂监控。

## 2.如何进行有分寸的主动关怀？（需要详细的提示词设计+RAG开发完成）

你的 LangGraph Router (`route_intervention_strategy`) 将根据“触发时机”和“情绪状态”选择不同的干预策略：

### 策略一：隐式伴随 (Implicit Companion) - 零认知占用

- **适用场景**：用户处于高认知负荷状态，但情绪开始出现轻微负面波动。
- **Agent 动作**:
  - **不说话**：绝对不发送任何文本。
  - **UI 调节**：通过 WebSocket 向前端发送指令，极其缓慢地将 EmotionHalo 的呼吸光晕从冷色调（白/蓝）调整为暖色调（淡黄），或将 BreathMotion 的悬浮频率调整到与“放松状态下的呼吸频率（约每分钟 6-10 次）”同步。
- **心理学原理**：利用环境心理学的“氛围效应”，在不打断用户心流的前提下，提供潜意识层面的情感支持。

### 策略二：微干预 (Micro-Intervention) - 低认知占用

- **适用场景**：在高认知负荷下出现“行为停滞”，或在低认知负荷下情绪持续负面。
- **Agent 动作**:
  - 前端弹出“微情绪弹窗 (Emotion Popover)”：一个极小的、半透明的、非模态的窗口从屏幕角落“轻轻浮现”（伴随 0.5 秒柔和动画）。
  - **内容**：
    - 文字：绝不超过 10 个字，如：“需要休息一下吗？”、“一个深呼吸，怎么样？”、“代码在编译，让眼睛离开屏幕几秒钟”。
    - 交互：提供两个按钮【好的 (执行工具)】和【忽略 (自动消失)】。
  - **工具调用 (Function Calling)**：如果用户点击“好的”，Agent 触发后端工具，如：调用一个 API 让前端播放一段 30 秒的白噪音、或者在屏幕上显示一个“呼吸引导”动画。

### 策略三：深度重构对话 (Deep Re-appraisal Dialogue) - 高认知占用

- **适用场景**：仅在用户明确处于“任务完成”或“长时间空闲”且负面情绪极高的状态下触发。
- **Agent 动作**:
  - 发起对话邀请：在聊天框中主动发送一条邀请：“看起来你现在有空，并且心情不太好。愿意聊聊刚才遇到的那个 Bug 吗？”
  - **RAG + CBT/ACT 介入**：一旦用户回应，立即启动我们之前设计的 `deep_intervention_node`，从知识库检索专业的认知行为疗法话术，进行结构化的、有引导性的对话，帮助用户识别并重构“自动化负面思维”。
