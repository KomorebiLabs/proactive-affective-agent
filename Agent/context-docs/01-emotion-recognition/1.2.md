## 情感捕捉

功能：按需调用云端多模态大模型（如Qwen-VL-Max）分析用户图像，获取文本描述的情感标签。（情感标签需要格外注意输出的格式和参数有哪些？）

输出：结构化描述，例如 

```json

  ],
  "cognitive_distortions": ["灾难化"],
  "scene_description": "用户正在看电脑屏幕，工作或学习状态，专注，眉头紧锁",
  "valence_arousal": {
    "valence": -0.7,
    "arousal": 0.8
  },
  "raw_response": "模型原始输出文本（可选）"

```

| 字段 | 类型 | 含义 | 示例 | 关联/用途 |
|------|------|------|------|-----------|
| timestamp | long | Unix 毫秒级时间戳 | 1742132400000 | 用于情感日志对齐 |
| primary_emotion | string | 主要情绪类别（需与吕思钒定义的情绪映射表一致） | "焦虑" | 直接用于 emotion_vector 的对应字段 |
| emotion_intensity | float | 情绪强度 0~1 | 0.8 | 用于 emotion_vector 的 intensity |
| confidence | float | 模型对自己判断的置信度 0~1 | 0.9 | 可选，用于决策（如低置信度时忽略或重新分析） |
| facial_cues | array of strings | 支持判断的面部特征描述列表 | ["眉头紧锁..."] | 可解释性，也可作为 Prompt 中的证据 |
| cognitive_distortions | array of strings | 推断出的认知扭曲类型（与吕思钒表一致） | ["灾难化"] | 可选，用于干预策略选择 |
| scene_description | string | 对场景的简要文本描述 | "用户正在看电脑..." | 辅助理解上下文 |
| valence_arousal | object | 效价和唤醒度，可选 | {"valence": -0.7, "arousal": 0.8} | 与 emotion_vector 的对应字段一致 |
| raw_response | string | 模型的原始文本输出（调试用） | "用户看起来..." | 可选，用于日志分析 |

认知扭曲（Cognitive Distortions）是认知行为疗法（CBT）中的核心概念，指个体在思维过程中出现的系统性偏差，导致对现实的误解，进而引发负面情绪。例如：
- 灾难化：将事情想得极其糟糕（“我肯定过不了”）
- 读心术：认为他人对自己有负面看法
- 非黑即白：极端思维（“要么完美，要么失败”）

在OCC模型中的作用：Agent可以将这个“事件”作为输入，结合任务上下文（例如，用户刚点击了“运行”按钮，代码报错了），去进行OCC归因分析。

### 如何整合两个模型参数的 JSON？程序化的数据聚合

在 LangGraph 的 analyze_emotion 节点中，你将从各个来源获取数据并组装成整合后的 JSON。这个过程是程序化的数据聚合，并非硬编码填空，而是通过调用工具和读取状态动态生成：

1. 客观证据：从 Redis 读取最新的感知数据（AU、头部姿态等），这些数据由感知微服务高频写入。
2. 主观分析：如果调用了 Qwen-VL，其结果已存入 state；否则可为 null。
3. 上下文：包括任务阶段（从会话控制器获取）、最近情感日志（从情感记忆库查询）。

示例代码：
```python
def assemble_analysis_input(state):
    # 从 Redis 获取最新感知数据（伪代码）
    perception = redis_client.get(f"emotion:realtime:{state['session_id']}")
    
    # 从状态获取 Qwen 分析（如果存在）
    qwen = state.get("qwen_analysis")
    
    # 获取最近情感日志（示例：查询过去1小时）
    recent = query_emotion_history(state["session_id"], hours=1)
    
    # 构建整合输入
    analysis_input = {
        "timestamp": int(time.time() * 1000),
        "session_id": state["session_id"],
        "objective_evidence": {
            "au_intensities": perception["au"],
            "head_pose": perception["head_pose"],
            "blink_rate": perception["blink_rate"],
            "audio": {
                "pitch": perception.get("audio_pitch"),
                "energy": perception.get("audio_energy"),
                "speaking": perception.get("is_speaking", False)
            },
            "focus_level": perception.get("focus_level", 0.5)
        },
        "subjective_analysis": qwen,  # 可能为 None
        "context": {
            "task_phase": state.get("task_phase", "unknown"),
            "recent_emotions": recent
        }
    }
    return analysis_input
```

- state 是原始感知数据，每帧更新，实时性强，但信息层级较低。
- emotion_vector 是高层认知结果，由 Agent 按需（如收到用户消息或定时）计算得出，融合历史与上下文。

## 输出中的置信度与分歧说明

LLM 的输出应包含一个字段 confidence 表示综合判断的置信度，并可选择性地输出 discrepancy_analysis 说明冲突是如何解决的。

| 字段 | 必要性 | 说明 |
|------|--------|------|
| emotion_assessment.primary_emotion | 必需 | 必须与吕思钒定义的情绪类型一致，否则前端无法映射。我们列出了10种常用情绪，覆盖常见情况。 |
| emotion_assessment.intensity | 必需 | 0-1 浮点数，与强度定义一致。 |
| emotion_assessment.valence | 推荐 | -1到1，用于更精细的情感分析，也便于与 PAD 模型对接。可由 LLM 输出，或根据情绪类型推算。 |
| emotion_assessment.arousal | 推荐 | 0-1，同上。 |
| emotion_assessment.cognitive_distortions | 推荐 | 与吕思钒的认知扭曲表一致，可为空。 |
| emotion_assessment.confidence | 必需 | 表示综合判断的可信度，用于决策层（如置信度低时可能不干预）。 |
| emotion_assessment.reasoning | 可选 | 用于调试和可解释性，生产环境可省略。 |
| intervention_decision.needed | 必需 | 是否需要进行任何形式的干预（包括 subtle）。 |
| intervention_decision.urgency | 推荐 | 当 needed=true 时，表示紧迫程度。 |
| intervention_decision.suggested_action | 必需 | 枚举值，对应三种动作：silent（无动作）、subtle（仅 UI 变化）、intervene（显式对话）。 |
| intervention_decision.ui_instruction | 必需 | 前端 UI 控制指令，color 和 pulse 必须存在，即使不干预也应有默认值（如 neutral, slow）。 |
| intervention_decision.recommended_strategy | 可选 | 用于日志记录或后续分析，也可作为干预时选择知识库的依据。 |
| intervention_decision.reply | 可选 | 如果 suggested_action=intervene，则应生成回复；否则为空。 |

- 添加 intervention_decision.ui_instruction 的默认值：即使不干预，也应给前端一个中性状态，例如 {"color": "neutral", "pulse": "slow"}，以避免前端无数据。

## 在 Prompt 中加入评估指南：

【评估指南】
- 当 AU4 > 0.6 且 AU12 < 0.3 时，强烈暗示负面情绪（愤怒/焦虑/恐惧）。
- 当 AU12 > 0.4 且其他正面 AU 也激活时，通常表示积极情绪。
- 若 AU4 和 AU12 同时高，可能为苦笑或复杂情绪，需结合其他线索。
- 低头 > 10° 且眨眼频率降低，可能提示疲惫或沮丧。
- 音调突然升高且能量高，常伴随高 arousal。
- 若客观参数与主观分析矛盾，优先考虑多组客观参数的一致性，并参考历史情绪。

## 情感时序分析示例

假设现在（15:00）用户皱眉，Agent查询过去2小时的情感日志：（例如）
查询条件：session_id = "sess_123", timestamp >= "2026-03-19T13:00:00"
返回记录：
- 13:15, 情绪=平静, intensity=0.3, 事件=IDLE
- 13:45, 情绪=沮丧, intensity=0.6, 事件=WORK, context=编译失败
- 14:20, 情绪=沮丧, intensity=0.7, 事件=WORK, context=再次报错
- 14:50, 情绪=焦虑, intensity=0.8, 事件=WORK, context=调试中
Agent可生成分析：
用户在过去2小时内已遭遇两次失败事件，沮丧情绪持续累积，当前焦虑强度高。当前皱眉事件可能并非孤立，而是连续挫折后的情绪爆发。
- 调整干预强度：需要更强力的支持。
- 归因细化：当前事件与历史事件关联，可能触发“习得性无助”相关干预。
