## 一、写入机制

### 1. 短期工作记忆（Redis）

**写入时机**：每轮交互（用户消息或AI回复）完成后，立即写入 Redis。

**数据结构**：Redis List，键名 `session:{session_id}:history`，每个元素为 JSON 字符串，包含 `role`、`content`、`timestamp`。

**实现要点**：
- 使用 `LPUSH` 将新消息插入列表头部，用 `LTRIM` 保留最近 N 条（如 20 条）。
- 同时更新会话最后活动时间戳，用于判断会话是否超时。

```python
import redis
import json
import time

r = redis.Redis(host='localhost', port=6379, decode_responses=True)

def add_message(session_id, role, content):
    key = f"session:{session_id}:history"
    message = json.dumps({
        "role": role,
        "content": content,
        "timestamp": int(time.time() * 1000)
    })
    r.lpush(key, message)
    r.ltrim(key, 0, 19)                     # 只保留最近20条
    r.setex(f"session:{session_id}:last_active", 7200, int(time.time()))
```

### 2. 结构化情景记忆（MySQL）

**写入时机**：
- **用户画像**：会话启动时写入基本信息；后续从对话摘要中动态提取新偏好时异步更新。
- **会话日志**：每轮 Agent 决策完成后，异步写入一条日志记录，包含感知快照、情感向量、干预决策、AI 回复等。

**实现要点**：通过消息队列（如 Celery）或线程池异步执行，避免阻塞主流程。

```python
# 异步写入日志示例
def log_interaction(session_id, user_message, perception_snapshot, emotion_vector, decision, reply):
```

### 3. 长期语义记忆（向量数据库 + 云端冷存储）

**写入时机**：
- **对话摘要**：当 Redis 短期记忆中的原始对话达到 20 条时，触发异步任务：将最旧的 15 条生成摘要，存入向量库，并从 Redis 中删除这 15 条。
- **情绪洞察**：会话结束时，对整个会话的所有日志进行总结，生成高层次的情绪模式洞察，存入向量库。

**实现要点**：使用 Embedding 模型（如 Sentence-Transformers）将文本向量化后存入向量数据库（如 Chroma），同时附带元数据（用户ID、类型、时间戳等）。

```python
import chromadb
from sentence_transformers import SentenceTransformer

model = SentenceTransformer('all-MiniLM-L6-v2')
chroma_client = chromadb.PersistentClient(path="./chroma_db")
collection = chroma_client.get_or_create_collection(name="long_term_memories")

def store_memory(user_id, text, memory_type="summary", metadata=None):
    vector = model.encode(text).tolist()
    id = f"{user_id}_{int(time.time())}"
    collection.add(
        documents=[text],
        embeddings=[vector],
        metadatas=[{
            "user_id": user_id,
            "type": memory_type,
            "timestamp": int(time.time()),
            **(metadata or {})
        }],
        ids=[id]
    )
```

## 二、检索机制

### 1. 短期记忆的读取

**读取时机**：每次 Agent 决策前（构建 Prompt 时），读取最近 N 条原始对话，用于保持对话连贯性。

**实现**：从 Redis List 中读取全部保留的对话（通常为 20 条以内），转换为文本格式。

```python
def get_recent_history(session_id):
    key = f"session:{session_id}:history"
    messages = r.lrange(key, 0, 19)   # 取最近20条
    history = []
    for msg in messages:
        data = json.loads(msg)
        history.append(f"{data['role']}: {data['content']}")
    return "\n".join(history)
```

### 3. 长期语义记忆的检索

**读取时机**：
- 深度干预前（`urgency=high`）：将当前情境（用户最新消息 + 感知数据摘要）向量化，检索相关历史摘要或洞察。
- 常规对话：若情绪强度超过阈值（如 >0.6），也可触发检索，增强个性化。

**实现**：将查询文本向量化，在向量库中搜索相似记忆，返回前 K 条。对于已冷存的记录，若需要实际内容，则从 OSS 异步加载。

```python
def retrieve_relevant_memories(user_id, query_text, k=3):
    query_vec = model.encode(query_text).tolist()
    results = collection.query(
        query_embeddings=[query_vec],
        n_results=k,
        where={"user_id": user_id, "is_cold": {"$ne": True}}   # 过滤掉已归档的冷存记录
    )
    memories = []
    for i in range(len(results['ids'][0])):
        if results['metadatas'][0][i].get('is_cold'):
            url = results['metadatas'][0][i]['cold_url']
            content = load_from_oss(url)         # 异步加载
        else:
            content = results['documents'][0][i]
        memories.append(content)
    return memories
```

检索到的记忆会以自然语言形式注入 Prompt，供 LLM 参考。

## 三、更新与遗忘机制

### 1. 短期记忆的更新与遗忘

- **更新**：每次新消息写入时，通过 `LTRIM` 自动淘汰超出数量限制的最旧消息。
- **遗忘**：会话结束时，Redis 键通过 TTL 自动过期（例如 2 小时无活动后删除），短期记忆自然消失。

### 2. 结构化记忆的更新与归档

- **更新**：用户画像通过 `INSERT ... ON DUPLICATE KEY UPDATE` 实现幂等更新；会话日志只追加不修改。
- **归档**：原则上不删除，但对超过 3 个月的日志可导出到离线存储，MySQL 中仅保留最近数据，以控制数据库大小。

### 3. 长期语义记忆的总结归纳与冷存储

#### 对话摘要生成（主动压缩）
当短期记忆累积到 20 条时，触发摘要生成，将最旧的 15 条原始对话交给 LLM 总结，存入向量库，并删除 Redis 中的这 15 条。这一机制既压缩了短期记忆，又形成了长期可检索的知识。

```python
def summarize_and_store(session_id, messages):
    prompt = f"请总结以下对话的核心内容和用户情绪变化：\n{messages}"
    summary = llm(prompt)
    store_memory(user_id, summary, "conversation_summary", metadata={"session_id": session_id})
    # 从Redis中删除已总结的原始记录
    r.ltrim(key, 0, 4)    # 只保留最近5条
```

#### 情绪洞察生成（会话级总结）
会话结束时，将本次会话的所有日志（可从 MySQL 读取）交给 LLM 总结，生成情绪模式洞察，存入向量库。

```python
def generate_session_insight(session_id, logs):
    prompt = f"分析以下用户对话日志，总结用户的情绪模式、常见认知扭曲及干预效果：\n{logs}"
    insight = llm(prompt)
    store_memory(user_id, insight, "session_insight", metadata={"session_id": session_id})
```

#### 长期记忆压缩与冷存储（定期任务）
定期（如每周）运行压缩任务，将超过一定时间（如 90 天）的旧摘要按用户分组，再次交给 LLM 提炼为更高级的“长期模式总结”，存入云端对象存储（如阿里云 OSS），并在向量库中仅保留指向冷存储的索引。这样既能保留高层次知识，又避免向量库无限膨胀。

```python
def compress_long_term_memory(user_id=None):
    cutoff = int(time.time()) - 90*86400
    old_records = collection.get(where={"timestamp": {"$lt": cutoff}, "type": "conversation_summary"})
    # 按用户分组，对每个用户的旧摘要进行二次总结
    user_summaries = {}
    for i, meta in enumerate(old_records['metadatas']):
        uid = meta['user_id']
        user_summaries.setdefault(uid, []).append(old_records['documents'][i])
    for uid, summaries in user_summaries.items():
        combined = "\n".join(summaries)
        prompt = f"以下是一段时间内用户的多段对话摘要，请提炼出用户长期的情绪模式、典型反应和干预效果：\n{combined}"
        long_pattern = llm(prompt)
        url = upload_to_oss(long_pattern, f"long_patterns/{uid}_{int(time.time())}.txt")
        # 在向量库中保留一条指向冷存储的记录
        collection.add(
            documents=[""],
            embeddings=[model.encode(long_pattern).tolist()],
            metadatas=[{
                "user_id": uid,
                "type": "compressed_pattern",
                "timestamp": int(time.time()),
                "is_cold": True,
                "cold_url": url
            }],
            ids=[f"{uid}_compressed_{int(time.time())}"]
        )
        # 可选：删除旧的摘要记录以节省空间
        # collection.delete(ids=old_records['ids'])
```

在检索时，若命中冷存记录，则从 URL 异步加载内容（可缓存到本地），确保仍能提供完整的上下文。

## 四、触发时机总结（按会话生命周期）

| 阶段 | 操作 | 记忆类型 | 说明 |
|------|------|----------|------|
| 会话启动 | 加载用户画像 | MySQL | 将静态画像拼入 System Prompt |
| 每轮交互 | 写入原始对话 | Redis | 追加到短期记忆 |
| 每轮交互 | 写入会话日志 | MySQL | 异步记录完整决策过程 |
| 短期记忆满（20条） | 生成摘要 → 存入向量库 | 长期语义 | 压缩最旧的15条，保留最近5条 |
| 深度干预前 | 检索相关长期记忆 | 向量库 | 根据当前情境语义检索 |
| 会话结束 | 生成会话洞察 → 存入向量库 | 长期语义 | 总结本次会话情绪模式 |
| 会话结束 | 用户画像动态更新 | MySQL | 从摘要中提取新偏好（可选） |
| 定期（每周） | 长期记忆压缩与冷存储 | 向量库+OSS | 合并旧摘要，归档至云端 |

这套机制保证了记忆系统既能实时响应，又能持续学习，且通过分层存储和自动压缩，在有限资源下实现了无限记忆的可能性。
