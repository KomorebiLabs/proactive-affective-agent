# AI agent核心之三：3.短期记忆和长期记忆的功能实现+联想（把情感和事件相结合）

- 识别长期模式：例如，用户在小时为单位的事件内都会皱眉，且沮丧强度逐次上升，可能预示累积压力。
- 预测情绪趋势：如果历史显示相似事件后常伴随焦虑，Agent可提前准备干预。
- 提供元认知反馈：如你所说，可以主动告知用户：“我发现您最近两次遇到问题时都显得很焦虑，需要一起聊聊吗？”——这种反馈本身就是一种高价值的心理支持。

回答：设计将记忆分为短期工作记忆、结构化情景记忆、长期语义反思记忆三层，分别采用Redis、MySQL、向量数据库作为存储载体，并明确了每层的业务场景和技术实现。这种分层既满足了不同访问频率和数据结构的需求，又兼顾了成本与性能，是一个非常成熟的设计思路。

#### 第一层：短期工作记忆 (Short-term Working Memory)

- **存储载体**：Redis
- **生命周期**：会话期间（可设置TTL，例如会话结束后2小时自动过期）
- **存储粒度**：以 session_id 为粒度
- **存储的具体数据**：
  1. **最近N轮原始对话记录**
     用于保持多轮对话的流畅性，确保Agent能看到最近的完整交互细节。
     - Redis数据结构：List（列表），每个元素是一条消息的JSON字符串。
     - 每个消息字段：
       ```json
       {
         "role": "user" | "ai",
         "content": "消息文本",
         "timestamp": 1742880000000
       }
       ```
     - 保留轮数：建议保留最近10轮原始对话（可根据token预算调整）。
  2. **对话摘要（可选，但推荐）**
     用于压缩更早的历史，避免无限增长。由后台异步任务生成。
     - Redis数据结构：String，键为 `session:{session_id}:summary`，值为摘要文本。
     - 摘要更新策略：当原始对话轮数超过N时，触发摘要生成（可用轻量级模型或LLM），新摘要覆盖旧摘要。
  3. **其他临时工作状态**
     如当前对话的临时变量、最近一次干预时间等，也可存储在Redis中，但更建议放在AgentState中。

- **为什么用Redis**：读写极快，支持TTL自动清理，完美匹配高频、临时的需求。

#### 第二层：结构化情景记忆与画像 (Structured Episodic & Profile Memory)

- **存储载体**：MySQL（关系型数据库）
- **生命周期**：长期保存，随用户生命周期
- **存储粒度**：按用户、按会话
- **存储的具体数据**：

**表1：用户画像表 (user_profile)**

存储用户的静态或半静态信息，供Agent在每次对话开始时加载。

| 字段名 | 类型 | 说明 | 示例 |
|--------|------|------|------|
| user_id | VARCHAR(64) | 用户唯一ID，主键 | "user_123" |
| session_id | VARCHAR(64) | 当前会话ID（可关联） | "sess_456" |
| name | VARCHAR(50) | 姓名 | "张三" |
| age | INT | 年龄 | 22 |
| user_level | VARCHAR(20) | 用户等级/分组 | "A" |
| preferences | JSON | 用户明确表达的偏好，如不喜欢白噪音 | {"no_white_noise": true} |
| created_at | DATETIME | 记录创建时间 | 2026/3/19 10:00 |
| updated_at | DATETIME | 最后更新时间 | 2026/3/19 10:00 |

**表2：会话日志表 (session_logs)**

记录每次Agent决策的输入输出，用于后期分析和画像提炼。

| 字段名 | 类型 | 说明 | 示例 |
|--------|------|------|------|
| log_id | BIGINT | 自增主键 | 1 |
| session_id | VARCHAR(64) | 会话ID | "sess_456" |
| timestamp | DATETIME | 日志时间 | 2026/3/19 10:05 |
| user_message | TEXT | 用户本次输入（如果有） | "我不行了" |
| perception_snapshot | JSON | 当时的感知数据快照（AU、音频等） | {"au": {"AU4":0.8}} |
| emotion_vector | JSON | 融合后的情感向量 | {"primary_emotion":"焦虑","intensity":0.8} |
| intervention_decision | JSON | 干预决策结果 | {"needed":true,"action":"intervene"} |
| ai_reply | TEXT | AI的回复 | "我们试试5-4-3-2-1法..." |
| task_performance | JSON | 任务完成情况（如答题正确率） | {"correct":0.6,"duration":120} |

- **为什么用MySQL**：这类数据高度结构化，需要精确的WHERE查询和统计，关系数据库是唯一合理的选择。

#### 第三层：长期语义与反思记忆 (Long-term Semantic & Reflective Memory)

- **存储载体**：向量数据库（如Chroma、Milvus）
- **生命周期**：长期保存，随用户积累
- **存储粒度**：每条反思或洞察为一个文档
- **存储的具体数据**：

每条记忆是一个向量化文档，包含：

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| id | string | 唯一ID | "mem_001" |
| user_id | string | 所属用户 | "user_123" |
| content | text | 反思文本（由大模型生成） | "用户每次遇到代码报错都会表现出高度焦虑，并伴有自我否定，建议提前引导其进行认知重构。" |
| type | string | 记忆类型：pattern/insight/summary | "pattern" |
| timestamp | datetime | 生成时间 | 2026/3/19 10:00 |
| metadata | json | 额外元数据，如相关情绪标签 | {"emotions":["焦虑","沮丧"]} |
| embedding | vector | 文本的向量表示（由Embedding模型生成） | [0.1, 0.2, ...] |

- **生成方式**：
  - 离线反思任务：每日定时运行，读取MySQL中的 session_logs，用大模型分析用户一天的情绪模式，生成反思文本。例如：
    ```text
    用户今日共进行5次调试，其中4次在报错后出现高强度焦虑（平均强度0.85），且伴随“灾难化”认知扭曲。建议未来遇到类似场景时，优先提供着陆技术并引导认知重构。
    ```
  - 将反思文本向量化后存入向量数据库。
- **检索方式**：
  当需要理解用户长期模式时，将当前情境（如用户最新情绪、最新消息）作为查询，用Embedding模型向量化后，检索向量数据库中相似度最高的若干条反思记忆，将其内容注入Prompt，帮助Agent做出更个性化的决策。
- **为什么用向量数据库**：情绪模式是模糊的语义，无法用精确SQL表达，必须依赖向量相似度搜索。

### 3.关于情感日志的撰写以及写入Redis的核心过程实现

将这个模块命名为 “情感时间序列记忆库”，其核心是：用历史情感轨迹辅助当前情绪判断与归因。它不仅能回答“这次皱眉是孤立事件吗？”，还能回答“用户最近是否持续处于低落状态，从而影响了对当前事件的反应？”

#### 日志记录格式设计

| 字段名 | 类型 | 说明 | 示例 |
|--------|------|------|------|
| timestamp | ISO 8601 字符串 | 事件发生时间 | 2026-03-19T15:00:00+08:00 |
| session_id | 字符串 | 会话ID，用于区分不同用户 | sess_123456 |
| emotion_vector | 对象 | 多模态融合输出的情感标签 | 见下方 |
| event_type | 字符串（枚举） | 用户当前活动的大类 | "WORK" |
| state | 对象 | 用户当前生理/行为状态 | 见下方 |
| context | 字符串（可选） | 简要上下文说明，如任务阶段 | "coding_debug" |

##### emotion_vector

```json
{
  "timestamp": 1742524801000,
  "session_id": "sess_123456",
  "primary_emotion": "焦虑",
  "secondary_emotion": null,
  "intensity": 0.85,
  "confidence": 0.90,
  "valence": -0.7,
  "arousal": 0.8,
  "dominance": 0.3,
  "cognitive_distortions": ["灾难化"],
  "evidence": {
    "au": {"AU4": 0.85, "AU12": 0.08},
    "qwen": "焦虑"
  },
  "history_context": {
    "recent_trend": "上升",
    "baseline_deviation": 0.2
  }
}
```

此结构由 Agent 的 analyze_emotion 节点生成，表示对用户当前情感状态的综合评估，融合了多模态客观证据与主观分析。

| 字段名 | 类型 | 说明 | 示例 | 来源 |
|--------|------|------|------|------|
| timestamp | integer (Unix ms) | 该情感向量的生成时间戳 | 1742524800000 | Agent |
| session_id | string | 会话ID | "sess_123456" | Agent |
| primary_emotion | string | 主要情绪类别（需与情绪映射表一致） | "焦虑" | LLM 融合 |
| secondary_emotion | string or null | 次要情绪（如果有） | "沮丧" | LLM 融合 |
| intensity | float (0-1) | 主要情绪强度 | 0.85 | LLM 融合 |
| confidence | float (0-1) | 本次评估的置信度 | 0.9 | LLM 融合 |
| valence | float (-1 to 1) | 效价：负→正 | -0.7 | LLM 或映射 |
| arousal | float (0-1) | 唤醒度：平静→激动 | 0.8 | LLM 或映射 |
| dominance | float (0-1) | 优势度（可选，PAD模型） | 0.3 | LLM 或映射 |
| cognitive_distortions | array of strings | 识别出的认知扭曲类型列表 | ["灾难化", "读心术"] | LLM |
| evidence | object | 支持该判断的证据摘要（可选） | {"au": {"AU4": 0.9}, "qwen": "焦虑"} | Agent |
| history_context | object | 历史情感上下文影响（可选） | {"recent_trend": "上升", "baseline_deviation": 0.2} | - |

- primary_emotion 必须取自吕思钒定义的情绪枚举列表，例如 ["焦虑", "沮丧", "平静", "开心", "疲惫", "愤怒", "恐惧", "厌恶", "惊讶", "中性"]。
- cognitive_distortions 必须取自认知扭曲类型表，例如 ["灾难化", "读心术", "非黑即白", "过度概括", "情绪推理", "贴标签", "个人化", "应该陈述"]。
- valence/arousal/dominance 可让 LLM 直接输出，或根据情绪类型和强度映射。

##### state

state 是用户当前生理/行为的原始或初步处理特征。它被高频写入 Redis，供 Agent 每次决策时读取。示例：

```json
{
  "timestamp": 1742524800123,
  "session_id": "sess_123456",
  "face": {"landmarks": [...]},
  "head_pose": {"pitch": -8.5, "yaw": 2.1, "roll": 1.3},
  "blink_rate": 0.5,
  "audio": {"pitch": 210.5, "loudness": 0.65, "mfcc": [-2.34, 1.21]},
  "au": {"AU4": 0.85, "AU12": 0.08, "AU15": 0.72},
  "focus_level": 0.3,
  "is_speaking": false
}
```

| 字段名 | 类型 | 说明 | 示例 | 来源 |
|--------|------|------|------|------|
| timestamp | integer (Unix ms) | 数据采集时间戳 | 1742524800123 | 感知模块 |
| session_id | string | 会话ID | "sess_123456" | 感知模块 |
| face | object | 面部关键点与姿态 | 见下方 | MediaPipe |
| hands | object | 双手关键点（可选） | 见下方 | MediaPipe |
| audio | object | 音频特征 | 见下方 | openSMILE |
| au | object | 面部动作单元强度 | 见下方 | HuggingFace AU 模型 |
| blink_rate | float (Hz) | 眨眼频率（每秒次数） | 0.5 | 计算值（基于眼部关键点） |
| focus_level | float (0-1) | 专注度估计 | 0.3 | 规则/模型（基于鼠标键盘等） |
| is_speaking | boolean | 是否正在说话 | FALSE | openSMILE 或 VAD |
| head_pose | object | 头部欧拉角（度） | {"pitch": -8.5, "yaw": 2.1, "roll": 1.3} | MediaPipe |
| gaze_direction | object | 视线方向（可选） | {"x": 0.2, "y": 0.1, "z": -0.8} | MediaPipe |
