## 一、项目一句话

> **婉晴AI是一个"感知→情感融合→干预决策→关怀回复"的循环AI系统。**
> Python感知服务负责采集摄像头和麦克风数据，Python Agent（LangGraph状态机）负责情感分析并决定是否发起关怀，Java作为HTTP网关负责与前端通信，前端负责展示情感可视化和婉晴立绘动画。

详细理解请阅读：
- **最简路径**：`A07_Agent整体运转逻辑.md`（Learning板块）
- **最全链路**：`T12_整体通信链路.md`（本板块）

### 3.2 核心数据流

```
用户操作/感知变化
       │
       ▼
感知服务(MediaPipe/openSMILE) ──WebSocket──→ 前端(实时展示)
       │                                        │
       └──Redis(emotion:realtime)───────────────┘
                │
                ▼
         Java后端(SSE)
                │
                ▼ HTTP POST
         Python Agent(LangGraph状态机)
                │
                ├──→ SILENT 路径：记录日志 → 返回结果
                ├──→ SUBTLE 路径：生成轻量回复 → 返回结果
                └──→ INTERVENE 路径：RAG检索 → 生成关怀回复 → 返回结果
                                              │
                                              ▼
                                        SSE流式推送 → 前端
```

## 五、核心模块详解

### T06 - LangGraph状态机（核心枢纽）

```
为什么LangGraph是核心？

传统LLM调用方式：
  用户输入 → 直接调用LLM → 返回结果
  问题：无法保持状态、无法多步骤推理、无法条件分支

LangGraph的优势：
  用户输入 → 状态机执行 → [节点A] → [节点B] → [条件路由] → [节点C/D]
                   ↑
            状态(State)贯穿始终
            每个节点都可以读取/写入状态
            支持条件分支（根据状态决定下一步）

婉晴AI的三条路径：
  SILENT    → 走神模式，仅记录日志
  SUBTLE    → 轻量干预，生成简单回复
  INTERVENE → 深度干预，RAG检索后生成关怀
```

### T07 - 情感融合节点（技术亮点）

```
OCC八维情感模型是什么？

传统的情感分类只有"喜怒哀惧"四种，而OCC模型将情感分为：
- 基础维度：喜悦、悲伤、愤怒、恐惧、厌恶、惊讶
- 复合维度：踏实感（安全/平静）、期待（对未来的预期）

为什么需要八维？
  用户A说"我通过了考试！"
  → 可能是喜悦（目标达成）
  → 可能是惊讶（意外）
  → 可能是期待（对未来更有信心）

  OCC八维可以同时表达多个情绪，更好地指导干预策略
```

### T08 - 干预决策节点（智能决策）

```
五因子评分模型设计原理

为什么需要多因子？
  - 只考虑情绪强度 → 频繁打扰用户
  - 只考虑情绪类型 → 忽视用户当前状态

五因子设计：
  score = W1×强度 + W2×优先级 - W3×打扰成本 + W4×趋势 + W5×置信度

核心洞察：
  - 打扰成本是负项：用户越专注，越不该打扰
  - 趋势是调节项：情绪正在恶化比已经恶化更值得关注
  - 用户反馈影响：拒绝次数多的用户，系统变得更保守
  - 用户主动发消息：跳过所有规则，直接响应
```
